# shadcn 组件演示

- 路由: `/demo`
- 状态: 已交付（61 组件 / 10 分类，单页）
- 版本: 0.2

## 目标

- 单页交互式呈现全部 61 个 shadcn/ui 组件，验证组件可用性与默认观感。
- 作为后续功能页的"组件手册"与标准用法参考（默认 props、最小可运行示例）。

## 非目标

- 不是公开文档站：无组件搜索、无单组件详情页、无多语言。
- 不是设计系统规范页：规范在 [docs/design-system.md](../../docs/design-system.md)。
- 无数据持久化；不引入新依赖。

## 用户与场景

- 开发者打开 `/demo`，按分类查找并验证组件的实际效果。
- 开发者在功能页复用组件前，参考标准用法和最小可运行配置。

## 页面与路由

| 路由 | 说明 |
|---|---|
| `/demo` | 主演示页（真相源），细则见 [app/demo/PAGE.md](../../app/demo/PAGE.md) |

## 功能需求

### 正常流程

1. 首页 CTA → 进入 `/demo`。
2. 按 10 个 section 分类浏览；每个组件提供独立、可识别的示例。
3. 交互验证: 浮层开关（Dialog/Sheet/Drawer/Popover 等）、toast 触发、图表渲染、日历、命令面板。
4. 顶部返回按钮回首页。

### 异常与边界

- 全部静态数据，无 loading / empty / error 页面状态。
- 浮层开合由本地 state 控制，无服务端错误路径。

## 验收标准

- 10 个 section 全部渲染，61/61 组件无缺漏（以 `components/ui/*.tsx` 实际导出和 `/demo` 导入清单为准）。
- 验证三件套通过。
- 无 console 错误；各浮层可正确打开/关闭；toast 可触发。

## 数据与接口

- 无接口；recharts 用静态数据数组。

## 风险与依赖

- 单文件 ~1210 行，后续维护成本高；功能页应参考示例写法而非拷贝 demo 代码。
